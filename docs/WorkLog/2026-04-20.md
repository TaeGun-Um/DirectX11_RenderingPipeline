# 2026-04-20 작업 기록

## 개요
프레임워크의 **오브젝트 수명 주기(Release 구조)** 를 지연 삭제 + fast-path 가드 방식으로 재구성. dead code(`Ext_ObjectDestroyManager`) 제거. HLSL ↔ C++ cbuffer **패킹 검증**을 `static_assert` 로 컴파일 타임에 이동. **Shader Hot Reload** (F6 키) 기능 신설. 작업 전반에 학습용 주석 추가.

---

## 1. Release 구조 개선

### 배경
기존 `Ext_Scene::Release()` 는 매 프레임 `Ext_Core::Update` 에서 호출되며, 내부에서는 Actors 맵의 **모든 액터를 순회하면서** `IsDeath()` 체크했다. 또 죽은 액터가 발견되면 그 액터의 모든 컴포넌트에 대해 `dynamic_pointer_cast<Ext_MeshComponent>` 를 돌려 카메라에서 빼내는 처리를 했다. 문제 지점:

- **죽은 게 없어도 전체 순회** — 200개 액터면 매 프레임 200번 비교
- **RTTI 캐스트 비용** — 죽은 액터의 컴포넌트마다 dynamic_cast
- **`Ext_ObjectDestroyManager`** 존재했지만 어디서도 호출되지 않는 dead code

### 설계 변경
세 가지 패턴을 조합:

**A. Scene dirty flag + Dead Actor 리스트**
- `Ext_Scene::PendingDeadActors` + `bHasDeadActor` 플래그 추가
- `Actor::Destroy()` 에서 소유 Scene 의 `MarkDeadActor(self)` 호출
- `Scene::Release()` 는 플래그 체크 후에만 Actors 맵 순회 → 평소엔 O(1)

**B. Actor 레벨도 동일 패턴**
- `Actor::PendingDeadComponents` 리스트 추가
- `Component::Destroy()` 에서 `MarkComponentDead(self)` 호출 (기존 `MarkDeadComponent()` 대체)
- `Actor::RemoveDeadComponents()` 가 리스트만 순회

**C. Component::OnDetachFromScene 가상함수**
- 기본은 no-op
- `Ext_MeshComponent::OnDetachFromScene()` 오버라이드 — 자기 카메라에서 스스로 제거
- `dynamic_pointer_cast` 제거 + Component 본인이 자기 정리 책임

### 관련 파일
- `DirectX11_Extension/Ext_Scene.{h,cpp}` — `MarkDeadActor`, `PendingDeadActors`, 새 `Release()`
- `DirectX11_Extension/Ext_Actor.{h,cpp}` — `Destroy()` override, `MarkComponentDead`, `PendingDeadComponents`, 개선된 `RemoveDeadComponents()`, 새 `Release()`
- `DirectX11_Extension/Ext_Component.{h,cpp}` — `OnDetachFromScene()` 가상함수, `Destroy()` 에서 `MarkComponentDead` 호출
- `DirectX11_Extension/Ext_MeshComponent.{h,cpp}` — `OnDetachFromScene()` override (Camera::RemoveMeshByActor 호출)
- `DirectX11_Extension/Ext_Camera.h` — `RemoveMeshByActor` public 이동 (MeshComponent 가 호출)

### 효과
| 상황 | 기존 | 개선 후 |
|---|---|---|
| 죽은 게 없는 프레임 (대부분) | 전체 액터 순회 (O(N)) | 플래그 체크 1회 (O(1)) |
| 죽은 게 있는 프레임 | 전체 순회 + RTTI 캐스트 | 대기열만 순회 (O(dead)) + 가상함수 디스패치 |

## 4. HLSL ↔ C++ 패킹 검증 (컴파일 타임)

### 배경
기존에는 `Ext_DirectXConstantBuffer::ChangeData` 에서 런타임에 `ByteWidth != _Size` 체크만 수행. HLSL cbuffer 와 C++ 구조체가 어긋나면 실행 중에 assert 가 터지는데, 어떤 필드가 어긋났는지 찾기 힘들었다.

### 변경
주요 cbuffer-mirror 구조체에 `static_assert` 추가:

| 구조체 | 기대 크기 | 위치 |
|---|---|---|
| `TransformData` | 528 bytes | `Ext_Transform.h` |
| `LightData` | 480 bytes | `Ext_Light.h` |
| `LightDatas` | 30736 bytes (`4 + 12 + 480 × 64`) | `Ext_Light.h` |
| `RenderingData` | 48 bytes | `Ext_MeshComponentUnit.h` |

각 assert 위에 **HLSL 레이아웃 주석**을 함께 둬서, 크기 계산 과정을 바로 확인 가능.

### 런타임 에러 메시지 개선
`Ext_DirectXConstantBuffer::ChangeData` 크기 불일치 메시지에 `expected=N, got=M` 출력 추가 — 디버깅 시간 단축.

## 5. Shader Hot Reload (F6)

### 구현 개요
런타임에 HLSL 파일 수정 → **F6 키** → 전체 VS/PS 재컴파일 → 셰이더 객체 교체.

### 구조
1. `Ext_DirectXShader` 에 `FilePath` 멤버 추가 — 재컴파일 시 재사용
2. `Ext_DirectXShader::Reload()` 가상함수 (기본 false)
3. `Ext_DirectXVertexShader::Reload()` / `Ext_DirectXPixelShader::Reload()` 구현
   - 임시 blob 에 먼저 컴파일 → 실패하면 기존 상태 보존
   - 성공 시 `BinaryCode` / `VertexShader` / `PixelShader` 교체
   - `BufferSetter.Clear()` 후 `ShaderResourceSetting()` 재호출 (리플렉션 재수집)
4. `Ext_DirectXResourceLoader::ReloadAllShaders()` — 모든 셰이더 순회 + 결과 로깅 (`OutputDebugStringA`)
5. `Ext_ResourceManager::GetAllNameResources()` — iteration 용 const getter 추가
6. `Ext_Core::Update` — `Base_Input::IsDown("ShaderReload")` 체크 후 호출
7. `Ext_Core::Start` — `"ShaderReload"` 키 등록 (`VK_F6`)
8. `Ext_DirectXBufferSetter::Clear()` — 내부 multimap 3개 비우는 전용 메서드

### 한계 / 주의사항
- **Material 의 BufferSetter 복사본** 은 Unit 초기화 때 복사되어 들어가 있어, Hot Reload 로 교체되지 않음
  → cbuffer 레이아웃(필드 추가/제거) 바꾸는 경우엔 재시작 권장. 픽셀 셰이더 로직 변경 정도엔 안전.
- **InputLayout** 도 VS signature 기반이라 signature 변경 시 스테일. 같은 조건에선 재시작 권장.
- **Debug 모드 전용 권장** — 컴파일 실패 시 이전 상태 유지하지만, 중간 상태에서 그래픽이 잠깐 튈 수 있음.

### 관련 파일
- `DirectX11_Extension/Ext_DirectXShader.{h}` — FilePath + virtual Reload()
- `DirectX11_Extension/Ext_DirectXVertexShader.{h,cpp}` — Reload override
- `DirectX11_Extension/Ext_DirectXPixelShader.{h,cpp}` — Reload override
- `DirectX11_Extension/Ext_DirectXResourceLoader.{h,cpp}` — ReloadAllShaders()
- `DirectX11_Extension/Ext_ResourceManager.h` — GetAllNameResources()
- `DirectX11_Extension/Ext_DirectXBufferSetter.{h,cpp}` — Clear()
- `DirectX11_Extension/Ext_Core.cpp` — F6 키 바인딩 + 호출

## 6. Release 구조 시각화 테스트 (ReleaseTestActor)

### 목적
리팩토링된 Release 경로가 눈으로 검증되도록, 매 사이클마다 **Cube/Sphere 10개 생성 → 1초 후 Destroy → 다시 10개 생성** 을 반복하는 테스트 액터를 신설. 프레임워크의 시각화 장점을 활용해 Destroy → PendingDeadActors → Scene::Release 흐름을 실시간 확인.

### 설계
- `DirectX11_Contents/ReleaseTestActor.{h,cpp}` 신설
- 상태:
  - `CurrentBatch` — 살아있는 자식 액터 `weak_ptr` 리스트 (소유권은 Scene, 이 액터는 관찰만)
  - `AccTime` — 사이클 누적 시간
  - `CycleCounter` — 이름 중복 방지용
  - 튜닝 3종 : `SpawnRadius` / `CyclePeriod` / `SpawnCount`
- 동작:
  1. `Update(dt)` 에서 `AccTime >= CyclePeriod` 체크
  2. 기존 배치 전원 `Destroy()` 호출 → Scene 의 PendingDeadActors 에 등록
  3. 같은 프레임 말 `Scene::Release` 가 실제 정리
  4. 새 배치 스폰 — 원형, Cube/Sphere 교대 (시각 구분)
  5. `CycleCounter++`

### 배치
- `RenderScene` 초기화에서 캐릭터 왼쪽 `(-250, 80, 0)` 에 1개 생성
- 기본값: 반경 120, 1초 주기, 10개
- 불필요하면 `RenderScene.cpp` 의 한 줄만 주석 처리하면 꺼짐

### 검증 포인트
실행 시 확인:
- **시각** — 1초마다 10개가 나타났다 사라지는 패턴 무한 반복
- **끊김 없음** — Release 가 한 프레임 내에 안전 처리
- **메모리** — VS Diagnostic 으로 누적 없이 안정 유지
- **Hot Reload 병행** — 이 테스트 돌리며 F6 눌러도 서로 간섭 없음

### 관련 파일
- `DirectX11_Contents/ReleaseTestActor.{h,cpp}`
- `DirectX11_Contents/RenderScene.cpp`
- `DirectX11_Contents/DirectX11_Contents.vcxproj` / `.filters`

## 7. ActorsUpdate iterator 무효화 버그 수정 (ReleaseTestActor 실험 중 발견)

### 증상
ReleaseTestActor 를 돌리자 **삭제 시점 근처에서 예외**:
```
예외: 읽기 액세스 위반
this 가 0xDDDDDDDDDDDDDDDD
Ext_Object::IsUpdate() 에서 crash
```
`0xDDDD...` = VS Debug CRT **freed-heap 마커**. 이미 해제된 메모리 재접근.

### 원인
`Ext_Scene::ActorsUpdate` 가 `Actors[Order]` 벡터를 range-for 로 순회하는 중, ReleaseTestActor 내부에서 `Scene->CreateActor<CubeActor>()` 호출 → 같은 벡터에 `push_back` → 벡터 재할당 → range-for 가 잡은 참조가 dangling.

```cpp
for (const std::shared_ptr<Ext_Actor>& CurActor : ActorList) // 벡터 요소 참조
{
    CurActor->Update(...);  // → ReleaseTestActor::Update → CreateActor → push_back
                            //   재할당 발생 → CurActor 가 freed 가리킴
    // 다음 iter 에서 freed pointer 역참조 → 0xDDDD... crash
}
```

### 수정
ActorList 를 **스냅샷 복사** 후 복사본 순회. 이번 프레임에 만든 새 액터는 자연스럽게 다음 프레임부터 Update. `shared_ptr` 복사 비용은 atomic refcount 증가로 저렴.

```cpp
for (auto& [Key, ActorList] : Actors)
{
    std::vector<std::shared_ptr<Ext_Actor>> Snapshot = ActorList;
    for (const auto& CurActor : Snapshot)
    {
        if (!CurActor || !CurActor->IsUpdate() || CurActor->IsDeath()) continue;
        CurActor->Update(_DeltaTime);
    }
}
```

### 교훈
- **순회 중 컨테이너 수정은 위험** — 특히 `std::vector::push_back` 은 재할당 시 iterator/reference 전부 무효화
- Destroy 는 이미 "지연 삭제" 로 이 문제를 회피했지만 **Create 쪽은 놓침** — 이번에 발견
- 스냅샷 복사 패턴이 표준 해법. 더 무거운 프레임워크면 deferred-create 큐도 고려 가치

### 관련 파일
- `DirectX11_Extension/Ext_Scene.cpp` — `ActorsUpdate` 에 Snapshot 복사
